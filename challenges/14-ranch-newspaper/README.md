## 📖 今回の事件

牧場で、新聞「ランチ・タイムズ」を作ることになった！ 📰
朝のようすと、夕方のようすをくらべる記事にしたい。
記者が、朝の記録をとるプログラムを書いてくれた。実行してみよう。

```text
🌙 ピコ は 夜ふかしした…… HP が 4 になった
☀️  朝の記録: ピコ HP 4
🍎 ピコ は もぐもぐ…… HP 4 → 6
🌙 夕方のピコ: HP 6
📰 朝の記事を読みかえすと…… ピコ HP 6
😱 朝の記事まで、夕方の HP になってる！？
```

朝の記録には、たしかに「HP 4」と書いてあった。
なのに、夕方に読みかえすと「HP 6」に変わっている！ 事件のコードを見てみよう。

```python
def broken_record(monsters):
    return list(monsters)      # 本人の名札を、そのまま並べているだけ！
```

この事件、どこかで見覚えがない？ 🕵️

---

## 🤔 書く前に① 名札は、昔のすがたを覚えていない

第07章を思い出そう。**変数やリストに入っているのは、本人を指す名札** だったね。

`broken_record` が作ったリストに入っているのも、**ピコ本人の名札**。
だから、あとでピコが食べて HP が 6 になると、記録のリストから見ても HP 6 になる。

```text
  朝の記録 ──→ 🟦 ピコ本人（HP 4）
                    │ もぐもぐ
  朝の記録 ──→ 🟦 ピコ本人（HP 6）  ← 同じ本人を見ているので、記録も変わって見える
```

名札は、本人の **今のすがた** を指すだけ。**昔のすがたは覚えていない** んだ。

---

## 🧩 書く前に② 記録は、その時の数字を「写す」

新聞に必要なのは、本人ではなく、**その時の数字**。
だから、記録係 `take_record`（`ranch_tools.py` に用意してあるよ）は、こうしている。

```python
record.append({
    "name": monster.name,
    "hp": monster.hp,          # その時の HP の「数字」を写す
    "happy": monster.happy,
    ...
})
```

辞書に入っているのは、**ピコ本人ではなく、HP 4 という数字**。
あとでピコの HP が変わっても、写した数字は 4 のまま。
写真を撮るようなものだね。📸 写真の中のピコは、もう変わらない。

| | 中身 | あとで本人が変わると |
|---|---|---|
| 事件のコード | 本人の名札 | 記録も変わって見える |
| `take_record` | その時の数字を写したもの | 記録は変わらない |

## 💡 書いた後に: 何が起きたの？

### 事件の解決: 記録は、写しだった

新聞の記事を見てみよう。

```text
   ピコ   HP  4 →  3   ごきげん  50 →  70
```

朝の記録は、ちゃんと **HP 4** のまま。`take_record` が、その時の数字を **写して** いたからだよ。
本人の名札（第07章）と、その時の値の写し。ちがいが分かれば、もう同じ事件は起きないね。

### 君が書いたのは、「お願い」だけ

TODO で書いたコードを、もう一度見てみよう。

```python
mina.recruit(piko)            # トレーナーにお願い
trainer.care_all(2)           # トレーナーにお願い
trainer.use_on_team(toy)      # トレーナーにお願い
save_newspaper(...)           # 新聞係にお願い
```

HP の計算も、遊び方も、バリアも、画像の描き方も、1行も書いていない。
それなのに、牧場の1日がまるごと動いて、新聞までできた。

**それぞれの部品が、自分の仕事を知っている。だから、組み合わせるだけで大きなものが作れる。**
これが、第04章からずっと学んできた **オブジェクト指向** の考え方だよ。🎉

### 1日の中で、だれがだれに頼んだ？

```text
run_morning(mina, おやつベル)
 ├ mina.care_all(2)                   トレーナー → 全員の eat(2)
 │    └ ピコ.eat(2) / フワ.eat(2) / ガード.eat(2)
 └ mina.use_on_team(おやつベル)       トレーナー → 道具の use
      └ おやつベル.use(ピコ)           道具 → モンスターの eat(3)
           └ ピコ.eat(3)

mina.use_on_team(ボール)              トレーナー → 道具の use
 └ ボール.use(フワ)                    道具 → フワの play
      └ フワ.play()                     ← FloatingMonster の play（ふわふわ！）
```

1つの号令が、トレーナー → 道具 → モンスターと、**バトンのように** 渡っていく。
どの部品も、自分の仕事しかしていない。でも、つながると大きな仕事になるんだ。

```python
def take_record(monsters):
    record = []
```

### ① チームに、直接 `append` した


動くけど、`recruit` の「同じ本人は入れない」「3匹まで」というルールを通らない。

`use_on_team` を先にすると、おやつベルのあとにごはん、という順番になる。

### ③ MVP に、名前を返した

```python
return best.name
```

「🏅 今日のMVP」が出ないし、新聞の MVP も分からなくなる。**本人** を返そう（第07章）。

### ④ 記録の順番を、逆に渡した

```python
save_newspaper(evening, morning, mvp)
```

新聞の「朝 → 夕方」が反対になってしまう。**朝・夕方・MVP** の順だよ。
