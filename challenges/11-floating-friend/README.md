## 🎯 この章でできるようになること

- ある設計図を **受けついで**、新しい設計図を作れる（**継承**）
- 受けついだ設計図の、**一部のメソッドだけを書きかえ** られる（**オーバーライド**）
- 書かなかったメソッドは、**親の設計図のものがそのまま使える** と分かる
- 「〜を持っている」と「〜の一種である」のちがいを説明できる

## 📖 今回の事件

牧場に、ふわふわ浮かぶおばけの **フワ** がやってくる！ ☁️👻
フワは、遊んでもあまりつかれない子。だから、スタッフが Monster の設計図を **まるごとコピー** して、
フワ用の設計図 `CopiedFuwa` を作った。実行してみよう。

```text
⚽ ピコ は 元気に遊んだ！ ごきげん 90  HP 1 → 0
   4回目 → フワ（コピー） HP -2
😱 ピコは 0 で止まったのに、コピーしたフワは HP がマイナス！
   Monster の play は直したのに、コピーの方は古いルールのままだった……
```

コピーの `play` を見てみよう。

```python
class CopiedFuwa:
    ...
    def play(self):
        self.happy = self.happy + 10
        self.hp = self.hp - 3        # 古いルールのまま！ 0 で止める行がない
```

第05章で、Monster の `play` には「HP を 0 より小さくしない」ルールを足したよね。
でも、そのルールを足す **前に** コピーしていたから、コピーの方には入っていなかった。

**コピーすると、同じコードが2か所にできる。片方を直しても、もう片方は直らない** んだ。😱

## 🤔 書く前に① 「持っている」と「〜の一種である」

第09章で、「トレーナーは、モンスターを **持っている**」という関係を学んだね。
今回は、別の関係が出てくるよ。

| 関係 | 例 | Pythonでは |
|---|---|---|
| 〜を **持っている** | トレーナーは、モンスターを持っている | 属性に入れる（`self.team`） |
| 〜の **一種である** | フワは、モンスターの一種である | **継承**（今回！） |

フワは、名前も HP もあるし、ごはんも食べるし、眠りもする。
つまり、フワは **モンスターの一種**。ただ、**遊び方がちょっとちがう** だけなんだ。

> 🍙 おにぎりで考えよう。「梅おにぎり」も「鮭おにぎり」も、**おにぎりの一種** だよね。
> にぎり方や、のりの巻き方は同じ。ちがうのは **中の具** だけ。
> 全部を一から作り直さず、ちがうところだけ変えればいいんだ。

## 🧩 書く前に② 継承: 親の設計図を受けつぐ

モンスターの一種を作る時は、こう書くよ。

```python
class FloatingMonster(Monster):
    ...
```

`class` の行で、名前のうしろの **カッコの中に、受けつぐ設計図** を書く。
これを **継承**（けいしょう）と呼ぶよ。

| 呼び方 | この章では |
|---|---|
| **親クラス**（受けつがれる方） | `Monster` |
| **子クラス**（受けつぐ方） | `FloatingMonster` |

子クラスは、親クラスのメソッドを **全部受けつぐ**。
だから `FloatingMonster` の中に何も書かなくても、`__init__` も `__str__` も `eat` も `sleep` も使えるんだ。

```python
fuwa = FloatingMonster("フワ", "おばけ", (230, 230, 255))   # 親の __init__ で誕生！
print(fuwa)                                                # 親の __str__ で自己紹介！
fuwa.eat(2)                                                # 親の eat で食べる！
```

Pythonは、`fuwa.eat(2)` と言われると、まず `FloatingMonster` の中で `eat` を探す。
見つからなければ、**親の `Monster` の中を探して**、それを使ってくれるんだ。

```text
fuwa.eat(2)
  ① FloatingMonster に eat はある？ → ない
  ② 親の Monster に eat はある？    → ある！ これを使う（self は フワ）
```

## 🔍 書く前に③ オーバーライド: 一部だけ書きかえる

フワの遊び方だけを変えたい時は、子クラスの中に **親と同じ名前のメソッド** を書く。

```python
class FloatingMonster(Monster):
    def play(self):
        ...   # フワ用の遊び方
```

すると、`fuwa.play()` と言われた時、Pythonは ① で `FloatingMonster` の `play` を見つける。
**親の `play` までは探しに行かない** ので、フワ用の遊び方が使われるんだ。

これを **オーバーライド**（上書き）と呼ぶよ。

```text
fuwa.play()
  ① FloatingMonster に play はある？ → ある！ これを使う（親の play は使われない）

piko.play()
  ① Monster に play はある？ → ある！ ふつうの遊び方
```

大事なのは、**親の `Monster` は1行も変わらない** こと。
ピコは今までどおりの遊び方、フワだけがふわふわの遊び方になるよ。

## 🔍 書く前に④ 同じ合図で、ちがう遊び方

第10章のボールを思い出そう。

```python
class Ball:
    def use(self, monster):
        if monster.is_tired():
            return False
        monster.play()
        return True
```

ボールは、相手がピコかフワかを **調べていない**。`monster.play()` と頼むだけ。
それでも、相手がフワなら、フワの `play`（オーバーライドしたもの）が動く。

第10章では「道具の種類がちがっても同じ合図」だった。
今回は「**モンスターの種類がちがっても同じ合図**」。同じしくみが、継承でも働くんだ。

## 📇 ことばカード

| ことば | 意味 | この章では |
|---|---|---|
| 継承（けいしょう） | 親の設計図を受けついで、新しい設計図を作ること | `class FloatingMonster(Monster):` |
| 親クラス / 子クラス | 受けつがれる方 / 受けつぐ方 | `Monster` / `FloatingMonster` |

| 〜の一種である（is-a） | 継承で表す関係 | フワは、モンスターの一種 |

## 💡 書いた後に: 何が起きたの？

### 事件の解決: コードは1か所だけ

`FloatingMonster` の中に書いたのは、`play` と `is_tired` の **2つだけ**。
`__init__`・`__str__`・`eat`・`sleep`・`take_damage`……は、全部 **親の `Monster` のもの** を使っている。

もし Monster の `eat` にルールを足したら？ フワの `eat` も、**自動で新しいルールになる**。
コピーとちがって、同じコードが2か所にないからね。

| | コピー（事件） | 継承（君のコード） |
|---|---|---|
| 書いたコード | 全部（`__init__` から何から） | ちがうところだけ（`play`・`is_tired`） |
| 親を直したら | コピーは古いまま | 子も自動で新しくなる |

### 同じボールで、ちがう結果

```text
--- 1回目 ---
⚽ ピコ は 元気に遊んだ！ ごきげん 60  HP 6 → 3
☁️  フワ は ふわふわ遊んだ！ ごきげん 60  HP 6 → 5
```

ボールも、トレーナーも、相手がフワかどうかを調べていない。
`monster.play()` と頼まれたフワが、**自分の設計図の `play`** を使った。
第10章の「同じ合図」が、モンスター同士でも働いたね。

### ふえるのは、ちがうところだけ

継承は「なんでもまとめる魔法」ではない。
名前や色がちがうだけなら、`Monster("ナナ", ...)` のように **属性の値を変えれば十分**。
**ふるまい（メソッドの中身）がちがう時** に、継承を使おう。

<details>
<summary>🎁 おまけ: 「この子は、モンスターの一種？」を調べる isinstance（クリックで開く）</summary>

第06章の `type()` で調べると、こうなる。

```python
print(type(fuwa) is Monster)          # False ← フワの設計図は FloatingMonster
print(type(fuwa) is FloatingMonster)  # True
```

「モンスターの一種かどうか」を知りたい時は、`isinstance`（イズ・インスタンス）を使うよ。

```python
print(isinstance(fuwa, Monster))      # True ← 親をたどって、モンスターの一種だと分かる
print(isinstance(piko, FloatingMonster))  # False
```

ただし、`if isinstance(...)` で **動きを分ける** のは、第10章の事件と同じ形になってしまう。
動きを変えたい時は、オーバーライドで **その子自身に任せよう**。
`isinstance` は、「確かめたい時」に使う道具だよ。

</details>

## ⚠️ ありがちなまちがい

<details>
<summary>⚠️ クリックで開く（エラーが出た時や、うまく動かない時に読もう）</summary>

### ① 親を書き忘れた

```python
class FloatingMonster:       # ← (Monster) がない！
```

```text
TypeError: FloatingMonster() takes no arguments
```

「FloatingMonster は、引数を受け取らない」という意味。
親を受けついでいないので、誕生セット係（`__init__`）がどこにもないんだ。

### ② `self` を書き忘れた

```python
def play():
```

```text
TypeError: FloatingMonster.play() takes 0 positional arguments but 1 was given
```

オーバーライドしても、メソッドの最初の引数は `self`。第05章と同じだよ。

### ③ メソッドの名前が、親とちがう

```python
def fuwa_play(self):         # ← play ではない！
```

エラーにならないけど、ボールは `play()` を頼むので、**親の `play`** が使われてしまう。
オーバーライドするには、**親とまったく同じ名前** にしよう。

### ④ 字下げがずれて、クラスの外に書いた

```python
class FloatingMonster(Monster):
    """..."""

def play(self):              # ← 字下げがない！ クラスの外の関数になった
```

エラーにならないけど、フワの `play` にならない。メソッドは、`class` の中に **4つ下げて** 書こう。

</details>
