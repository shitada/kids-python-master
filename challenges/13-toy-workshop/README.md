## 📖 今回の事件

ミナは道具が大好き。ベル・笛・リボン・たいこ……どれも、使える回数が決まっている。
ミナは、残り回数を **全部自分で覚える** ことにした。実行してみよう。

```text
🔎 ミナが覚えていること: {'name': 'ミナ', 'team': [], 'bell_left': 2, 'whistle_left': 3, 'ribbon_left': 1, 'drum_left': 5}
😱 道具が増えるたびに、トレーナーの属性が増えていく！ 第04章の「変数だらけ」に逆もどり……
```

事件のコードを見てみよう。

```python
class TrainerWithCounters:
    def __init__(self, name):

        self.team = []
        self.bell_left = 2        # ベルの残り回数
        self.whistle_left = 3     # 笛の残り回数

```

道具が1つ増えるたびに、トレーナーの設計図を直さないといけない。
しかも、リョウもベルを持っていたら、リョウの設計図にも `bell_left` が必要……。

## 🧩 書く前に② 残り回数は、だれが覚える？

事件では、ベルの残り回数を **トレーナー** が覚えていた。
でも、よく考えてみよう。「残り回数」は、だれの情報？

> 🔋 スマホの電池の残りは、だれが覚えている？
> 持ち主のあなたではなく、**スマホ自身** だよね。
> あなたが新しいスマホを買っても、自分の頭の中に「新しいスマホの電池」を覚える場所を足したりしない。

道具の残り回数も同じ。**道具自身** が覚えるのが自然なんだ。

```python
class MyToy:
    def __init__(self, name, max_uses):
        self.name = name
        self.max_uses = max_uses
        self.left = max_uses       # 残り回数は、道具本人が覚える
```

こうすると、ベルを2個作っても、**それぞれが自分の残り回数** を持つ（第04章のインスタンスと同じ）。
トレーナーの設計図は、道具が何個増えても、**1行も変えなくていい**。

> 💡 **設計のコツ: 情報は、その情報を一番よく知っている人（オブジェクト）に持たせる。**

## 🔍 書く前に③ 入口は、第10章と同じ `use(monster)`

君の道具は、牧場の道具箱に入れて使ってもらいたいよね。
第10章で、道具の **約束** を決めた。

| 約束 | 内容 |
|---|---|
| メソッドの名前 | `use` |
| 受け取るもの | モンスター1匹 |
| 返す答え | 使えたら `True`、使えなかったら `False` |

この約束を守れば、`use_all` も `Trainer.use_on_team` も、**君の道具のことを何も知らないのに** 使ってくれる。
自由に設計していいけど、**入口（約束）だけは守る**。これが、ほかの部品と協力するためのルールだよ。

### 設計メモ `DESIGN` で、道具を決めよう

ファイルの `DESIGN` に、君の道具の設計が書いてあるよ。**自由に書きかえてOK**。

```python
DESIGN = {
    "name": "おやつベル",
    "icon": "🔔",
    "max_uses": 2,
    "effect": "eat",        # "eat"（食べる）/ "play"（遊ぶ）/ "sleep"（眠る）
}
```

`effect` を変えたら、`use` の中でモンスターに頼む仕事も、それに合わせて変えよう。
（`"play"` なら `monster.play()`、`"sleep"` なら `monster.sleep()`）

## 🔍 書く前に④ クラスにしなくていいもの

「なんでもクラスにすればいい」わけではないよ。
温泉の入場料を考えよう。「つかれている子は 25円、それ以外は 50円」。

| 質問 | 入場料の計算では |
|---|---|
| 覚えておくことはある？ | **ない**（毎回、モンスターを見て計算するだけ） |
| 何回使っても、同じ答え？ | 同じモンスターの状態なら、同じ答え |

覚えておくことがないなら、クラスにしても `self` に入れるものがない。
**ふつうの関数** で十分なんだ。

```python
def calc_fee(monster):
    ...
```

| 作りたいもの | おすすめ |
|---|---|
| 覚えること ＋ できること がある（残り回数のある道具） | **クラス** |
| 計算するだけ（入場料） | **関数** |
| 決まった対応表（種族の相性） | **辞書**（第08章の `STRONG_AGAINST`） |

## 🔮 実行する前に、予想しよう！

おやつベル（2回まで使える）を、2個作った。

```python
toy_a = MyToy("おやつベル", 2)
toy_b = MyToy("おやつベル", 2)
toy_a.use(piko)
toy_a.use(piko)
print(toy_a.use(piko))   # 3回目は？
print(toy_b.left)        # B の残りは？
```

<details>
<summary>こたえを見る</summary>

**`False` と `2`**。

A は2回使って空っぽなので、3回目は使えない（`False`）。
B は1回も使っていないので、残り 2 回のまま。
2個の道具は、同じ設計図から作られた **別々のインスタンス**。残り回数も別々に覚えているよ。

</details>

## 💡 書いた後に: 何が起きたの？

### 事件の解決: トレーナーは、何も変わっていない

君の道具は、残り回数を **自分で** 覚えている。
だから、道具が何種類増えても、トレーナーの設計図には `bell_left` のような属性を足さなくていい。
**情報を、その持ち主に持たせた** から、変数だらけにならなかったんだ。

### 君の道具が、道具箱に入れた！

```text
📋 結果
   🎾 ボール → ✅ 使えた
   🍪 おやつ → ✅ 使えた
   🔔 おやつベル → ✅ 使えた
```

`use_all` は第10章で作った関数。**君の道具のことは何も知らない**。
それでも使えたのは、君が `use(monster)` という **入口の約束** を守ったから。
設計は自由でも、約束を守れば、ほかの部品と協力できる。これが、オブジェクト指向のいちばんの楽しさだよ。🎉

### 設計のふりかえり: 君の道具は、いい設計？

次のチェックリストで、君の道具を見直してみよう。全部 ✅ なら、すてきな設計だよ。

| チェック | おやつベルでは |
|---|---|
| 覚えることは、その道具自身が持っている？ | ✅ 残り回数は `self.left` |
| 1つ作っても、2つ作っても、それぞれ別々に動く？ | ✅ A と B は別々の残り回数 |
| ほかの部品との約束（入口）を守っている？ | ✅ `use(monster)`、`True` / `False` |
| ほかの部品の値を、直接さわっていない？ | ✅ モンスターには `eat` で頼んでいる |
| 名前を見れば、何をするメソッドか分かる？ | ✅ `use`・`refill` |

### クラスにするか、しないかを選べた

道具は「残り回数」を覚えるので **クラス**。入場料は覚えることがないので **関数**。
クラスは、とても便利な道具。でも、**いつも使う必要はない**。
「覚えることがあるか？」を考えて選べるようになったら、君はもう設計者だ！

### ① `effect` と、頼む仕事がちがう

```python

...
```

エラーにはならないけど、TODOチェックで「設計メモの effect は play なのに、eat を頼んでいるよ」と出る。

### ② 残り回数をへらし忘れた

ずっと使えて、空っぽにならない。`self.left = self.left - 1` を足そう。

空っぽなのに、おやつを食べてしまう。**確かめてから、動く**（第08章）の順番にしよう。

```python
        ...
```

動くけど、`self` に覚えることが何もない。こういう時は、**ふつうの関数** で十分だよ。

## 🕵️ バグ探しクイズ

<details>
<summary>🕵️ クリックで挑戦する</summary>

ベルを2個作ったら、A を使っただけなのに、**B の残り回数も減ってしまった**。どこが悪い？

```python
class MyToy:
    left = 2

    def __init__(self, name, max_uses):
        self.name = name
        self.max_uses = max_uses

    def use(self, monster):
        if MyToy.left == 0:
            return False
        monster.eat(3)
        MyToy.left = MyToy.left - 1
        return True
```

<details>
<summary>こたえを見る</summary>

残り回数を、**設計図（クラス）** に1つだけ持たせている（第09章のクラス属性）。
`MyToy.left` は、全部の道具で共有されてしまう。
`__init__` の中で `self.left = max_uses` と作り、`use` の中でも `self.left` を使おう。

</details>
