## 🤔 書く前に① なぞの呪文を読みとこう

`<__main__.Monster object at 0x7f3a2c1b9e50>` は、実はちゃんと意味があるよ。

| 部分 | 意味 |
|---|---|
| `__main__` | いま実行している、このファイル |
| `Monster` | 設計図（クラス）の名前 |
| `object` | オブジェクト（＝誕生した1匹） |
| `at 0x7f3a...` | パソコンの記憶（メモリ）の中で、その子がいる **住所** |

つまり、Pythonはこう言っているんだ。

> 「このファイルの `Monster` 設計図から生まれた子が、**この住所に1匹いるよ**」

うそはついていない。でも、**名前も HP も分からない**。
Pythonは、モンスターをどう紹介すればいいのか知らないんだ。
**自己紹介のしかたは、設計図を書いた君が教えてあげる必要がある** よ。

> 💡 住所（`0x...` の部分）は、実行するたびに変わる。
> 2匹の住所がちがうことからも、「別々の子」だと分かるね。

## 🧩 書く前に② `__str__` は「自己紹介係」

自己紹介のしかたを教えるのが、`__str__`（ストラ / ダンダー・エス・ティー・アール）という **特別なメソッド** だよ。

```python
def __str__(self):
    return f"{self.name}（{self.kind}）Lv.{self.level}"
```

`__init__` と同じく、前後に `__` がついているね。
これは「**Pythonが、決まったタイミングで自動で呼ぶメソッド**」の印なんだ。

| 特別なメソッド | Pythonが自動で呼ぶタイミング | 係 |
|---|---|---|
| `__init__` | `Monster(...)` で **誕生した時** | 誕生セット係 |
| `__str__` | その子を **文字にする時**（`print` や f文字列） | 自己紹介係 |

`str` は「string（ストリング）＝文字列」の略。
`__str__` は「この子を文字列にするなら、こうしてね」というメソッドなんだ。

### `print(piko)` の裏側

`__str__` を作ると、`print(piko)` の時にPythonはこう動くよ。

```text
print(piko)
   ↓ 「ピコを文字にしなきゃ」
piko.__str__() を自動で呼ぶ
   ↓ self = ピコ
return で "ピコ（スライム）Lv.1" が返ってくる
   ↓
print がその文字を画面に出す
```

### `print` ではなく、`return` で返す！

ここが大事なポイント。`__str__` の中では **`print` しない**。
文字を **`return` で返す** だけにするよ。

なぜなら、`__str__` は `print` のためだけの係ではないから。
f文字列の中でも、同じ自己紹介が使われるんだ。

```python
print(f"今日のMVPは {piko} です！")
# → 今日のMVPは ピコ（スライム）Lv.1 です！
```

文字を返しておけば、`print` でも、f文字列でも、どこでも使える。
第05章の `is_tired()` と同じで、**答えを返すメソッド** なんだ。

## 🔍 書く前に③ `vars()` は「中身をのぞくルーペ」🔎

`vars(piko)` と書くと、ピコが覚えている属性を **全部** 見せてくれるよ。

```python
>>> vars(piko)
{'name': 'ピコ', 'kind': 'スライム', 'color': (90, 200, 250), 'level': 1, 'max_hp': 10, 'hp': 10, 'happy': 50}
```

この形、どこかで見覚えがない？ そう、**辞書** だ！

実はインスタンスは、**自分の属性を辞書のような箱にしまって覚えている** んだ。
`piko.hp` と書くと、Pythonはピコの箱の中から `"hp"` という名前のものを探してくれる。

> 🤔 「じゃあ、辞書を使えばいいんじゃない？」
>
> いい疑問！ 中身をしまう仕組みは、たしかに辞書に似ている。
> でもクラスには、辞書にはない2つの強みがあるよ。
> 1. **設計図（`__init__`）があるから、どの子も同じ属性を必ず持つ**
> 2. **メソッドがあるから、「できること」とルールもいっしょに持てる**
>
> 「データ」と「できること」がセットになったもの。それが **オブジェクト** だよ。

---

## 🔍 書く前に④ `type()` は「なにもの？」と聞く道具

`type(piko)` と書くと、「その子は **どの設計図から生まれたか**」を教えてくれるよ。

```text
type(piko)      → <class '__main__.Monster'>
type(piko.name) → <class 'str'>
type(piko.hp)   → <class 'int'>
type(ranch)     → <class 'list'>
```

`piko` が `Monster` クラスなのは分かる。でも、よく見て！
`"ピコ"`（文字列）は **`str` クラス**、`10`（整数）は **`int` クラス**、
リストは **`list` クラス** と出ている。

そう、**文字列も、数も、リストも、全部Pythonが用意したクラスのインスタンス** なんだ。
`"hello".upper()` や `ranch.append(...)` がドットで呼べたのは、
それらがメソッドを持ったオブジェクトだったからだよ。

君の `Monster` も、`str` や `list` と同じ仲間入りをしたってこと。
これが「Pythonの中は、オブジェクトだらけ」の意味だよ。🌏

## 💡 書いた後に: 何が起きたの？

### 事件1の解決: 自己紹介のしかたを教えた

`__str__` を書いただけで、`print(piko)` も、`print(momo)` も、
図鑑の f文字列の中も、**全部が自己紹介に変わった** ね。

自分で `piko.__str__()` と呼んだところは1つもない。
Pythonが「文字にしなきゃ」という時に、**自動で呼んでくれた** んだ。
`__init__` が「誕生の時」に自動で呼ばれたのと、まったく同じ仕組みだよ。

### 事件2の解決: タイプミスが「新しい属性」を作っていた

犯人はこの1行だったね。

```python
self.hapy = self.happy + 10     # happy の p が1つ足りない！
```

Pythonは、`self.hapy = ...` を見て、こう考えたんだ。

> 「`hapy` という属性はまだないな。じゃあ、**新しく作ろう**！」

だからエラーにならず、ごきげんは `hapy` という **別の箱** に入ってしまった。
本物の `happy` は 50 のまま、まったく変わらなかったわけだ。

ルーペで見た時、こうなっていたよね。

```text
   happy   : 50     ← 本物。変わっていない
   hapy    : 60     ← タイプミスで生まれた、なぞの箱
```

第04章の「観察コーナー」で、**外から属性をくっつけられてしまう** 話をしたね。
これはその仲間で、**メソッドの中でも、代入（`=`）で新しい属性が生まれてしまう** んだ。
だからこそ、

- 属性は `__init__` で全部用意しておく（何を覚えるかが設計図で分かる）
- あやしい時は `vars()` でのぞいて、`__init__` と見比べる

この2つが、牧場を守るコツだよ。🔎

### `print` は見せる、`return` は返す（もう一度）

| メソッド | していること |
|---|---|
| `show()` | 顔とバーを **画面に表示する**（`print` を使う） |
| `__str__()` | 自己紹介の **文字を返す**（`return` を使う） |

どちらも「自分のことを伝える」メソッドだけど、役わりがちがう。
`show()` は画面専用。`__str__()` は文字を返すから、f文字列の中など、どこでも使える。

## ⚠️ ありがちなまちがい

### ① `__str__` の中で `print` した

```python
def __str__(self):
    print(f"{self.name} です")
```

```text
TypeError: __str__ returned non-string (type NoneType)
```

「`__str__` が文字列ではないもの（`None`＝何もない）を返した」という意味。
`return` がないと、メソッドは `None` を返してしまうんだ。`print` ではなく `return` を使おう。

### ② 数字をそのまま返した

```python
def __str__(self):
    return self.hp
```

```text
TypeError: __str__ returned non-string (type int)
```

`__str__` は **必ず文字列** を返す約束。f文字列で `return f"HP {self.hp}"` のようにしよう。

### ③ `_` の数をまちがえた

```python
def _str_(self):      # ← 前後とも _ が1つずつしかない
```

これは **エラーにならない** のがやっかい。
Pythonは `_str_` を「ふつうのメソッド」だと思うので、`print(piko)` の時に呼んでくれず、
なぞの呪文のままになる。**前後とも `_` を2つずつ** 書こう。

### ④ f文字列の `f` を忘れた

```python
return "{self.name}（{self.kind}）"
```

画面に `{self.name}（{self.kind}）` と、そのまま出てしまう。
`{ }` の中を計算してほしい時は、文字の前に **`f`** をつけよう。
