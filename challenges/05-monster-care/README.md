## 🧩 書く前に② メソッド＝クラスの中に書いた関数

**メソッド** は、クラスの中に `def` で書いた関数のこと。
その設計図から生まれた子が **「できること」** になるよ。

今回のファイルには、もう完成しているお手本のメソッドがあるよ。

```python
class Monster:
    def __init__(self, name, kind, color):
        ...

    def sleep(self):
        """ぐっすり眠って、HPが満タンになる。"""
        self.hp = self.max_hp
        print(f"💤 {self.name} は すやすや…… HP が満タンになった！")

    def stay_up_late(self):
        """夜ふかしして、HPが6減る。でも 0 より小さくはならない。"""
        self.hp = self.hp - 6
        if self.hp < 0:
            self.hp = 0
        print(f"🌙 {self.name} は 夜ふかしした…… HP が {self.hp} になった")
```

`stay_up_late` は、HP を減らしたあとに「0 より小さくしない」という **牧場のルール** も守っているね。
この形は、あとの TODO 2 でそのまま使えるよ。

いままで作ってきた関数と、ほとんど同じだね。ちがうのは、この3つ。

| | ふつうの関数 | メソッド |
|---|---|---|
| どこに書く？ | ファイルのどこでも | **`class` の中**（1段下げて書く） |
| 最初の引数 | 自由 | **必ず `self`** |
| 呼び方 | `sleep()` | **`piko.sleep()`**（誰に頼むかをドットの左に書く） |

`piko.sleep()` は、「**ピコ、眠って！**」と頼んでいるように読めるね。
「誰が（主語）」＋「何をする（動き）」の順番になっていて、とても読みやすいんだ。

> 💡 クラスは **「覚えていること（属性）」と「できること（メソッド）」をセットにした設計図**。
> 第04章では属性だけだったけど、ここでやっと設計図が完成形に近づいたよ。

## 🔍 書く前に③ `self` には、誰が入っているの？

ここがこの章でいちばん大事なところ！ 👀

`eat` メソッドは、こう定義されているよ。

```python
def eat(self, amount):
```

引数は `self` と `amount` の **2つ**。
でも、使う時は `momo.eat(3)` のように **1つしか渡していない**。
`self` はどこから来たんだろう？

### ドットの左の子が、`self` になる

実は、Pythonは `momo.eat(3)` を、こっそりこう読みかえているんだ。

```python
momo.eat(3)
   ↓ Pythonの頭の中
Monster.eat(momo, 3)
```

```text
   Monster.eat( momo ,  3     )
                 │      │
   def eat( self ,  amount ):
```

つまり、**ドットの左に書いた子（momo）が、自動で `self` に入る** んだ。
だから `self` は自分で渡さなくていい。

- `momo.eat(3)` → `self` は **モモ**、`amount` は 3
- `piko.eat(5)` → `self` は **ピコ**、`amount` は 5

メソッドの中の `self.hp` は、モモから呼ばれた時は「モモのHP」、
ピコから呼ばれた時は「ピコのHP」になる。
**メソッドは1つしか書いていないのに、どの子にも使える** のは、この仕組みのおかげだよ。

> 🧪 **ためしてみよう:** ファイルの `momo.eat(3)` を `Monster.eat(momo, 3)` に書きかえて実行してみよう。
> 結果は同じになるはず！（ためしたら元にもどしてね）

### メソッドの中では、`self.` をつけて自分の属性を使う

メソッドの中で、自分の HP を使いたい時は **必ず `self.hp`** と書くよ。
ただの `hp` と書くと、Pythonは「この子の HP」だと分からない。

| 書き方 | 意味 |
|---|---|
| `self.hp` | **この子の** HP（ずっと覚えている属性） |
| `amount` | このメソッドが **受け取った値**（メソッドが終わると消える） |
| `before` | メソッドの中だけで使う **メモ用の変数**（終わると消える） |

## 🔍 書く前に④ 「する」メソッドと「答える」メソッド

メソッドには、大きく2つのタイプがあるよ。

| タイプ | 例 | していること |
|---|---|---|
| 🏃 **する** メソッド | `eat()` `play()` `sleep()` | 属性を変えたり、画面に表示したりする |
| 💬 **答える** メソッド | `is_tired()` | 質問に `return` で答えを返す |

`is_tired()` は「つかれてる？」と聞かれて、`True`（うん）か `False`（ううん）を **返す** メソッド。
返ってきた答えは、`if` でそのまま使えるよ。

```python
if piko.is_tired():
    piko.sleep()
```

`print` は「画面に見せる」だけで、プログラムには答えが返らない。
**`if` で使いたい答えは、`return` で返す** のがポイントだよ。

## 💡 書いた後に: 何が起きたの？

### `momo.eat(3)` を、1行ずつ追いかけよう

```python
def eat(self, amount):                    # self = モモ、amount = 3
    before = self.hp                      # before = 4（モモの今の HP をメモ）
    self.hp = self.hp + amount            # モモの HP = 4 + 3 = 7
    if self.hp > self.max_hp:             # 7 > 10？ → いいえ
        self.hp = self.max_hp             #（ここは動かない）
    print(f"🍎 {self.name} は もぐもぐ…… HP {before} → {self.hp}")
```

2回目の `momo.eat(5)` では、`self.hp` が 12 になって `if` が「はい」になり、10 にそろえられたね。
**同じメソッドでも、中身の値によって通る道が変わる** んだ。

### ルールは、1か所に書けば、ずっと守られる

「書く前に①」では、ごはんのたびに `if` を書く必要があった。
今は、ルールが **`eat` の中に1回だけ** 書いてある。
だから `eat` を100回呼んでも、ルールの書き忘れは起きない。

「HP のルールを知っているのは、モンスター自身」。
これが、オブジェクト指向の大事な考え方の1つ、
**「自分のことは、自分に任せる」** だよ。🙌

### メソッドがメソッドを使う、プログラムが文章みたいに読める

**ほとんど日本語の文章と同じ** だね。細かい計算は全部メソッドの中にしまわれているから、
使う側のコードは「何をしたいか」だけが見えるようになったんだ。

## ⚠️ ありがちなまちがい

<details>

### ① メソッドの `self` を書き忘れた

```python
def eat(amount):      # ← self がない！
```

```text
TypeError: Monster.eat() takes 1 positional argument but 2 were given
```

「eat は引数を **1個** 受け取るはずなのに、**2個** 来たよ」という意味。
え、`piko.eat(3)` は1個しか渡してないのに……？
そう、Pythonが **ドットの左のピコを、こっそり1個目として渡している** から2個になるんだ。
メソッドの最初の引数には、必ず `self` を書こう。

### ② 引数を渡し忘れた

```python
piko.eat()
```

```text
TypeError: Monster.eat() missing 1 required positional argument: 'amount'
```

「`amount` が足りない」という意味。何ぶん食べるかを `piko.eat(3)` のように渡そう。

### ③ メソッドの中で `self.` を書き忘れた

```python
def play(self):
    hp = self.hp - 3      # ← 左側に self. がない！
```

これはエラーにならない……けど、**HP が減らない**。
左側の `hp` は、メソッドの中だけのメモ用の変数になってしまい、
メソッドが終わると消えてしまうんだ。**この子の HP を変えたい時は `self.hp = ...`** だよ。

### ④ `( )` を書き忘れた

```python
if piko.is_tired:     # ← ( ) がない！
    piko.sleep()
```

これもエラーにならないけど、**ピコが毎回寝てしまう**。
`( )` がないと、メソッドを **呼ばず**、「メソッドそのもの」を `if` で調べてしまう。
メソッドそのものは、いつも `True` あつかいになるんだ。
**仕事を頼む時は、必ず `( )` をつける** と覚えよう。

### ⑤ `return` の代わりに `print` を書いた

```python
def is_tired(self):
    print(self.hp <= 3)    # ← 画面には出るけど……
```

画面に `True` と出るので、できた気がする。でも、`if piko.is_tired():` の時に
返ってくる答えは `None`（何もない）になってしまう。
**プログラムに答えを渡したい時は `return`** だよ。

</details>
