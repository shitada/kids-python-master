## 🤔 書く前に① 新しい子が生まれるのは、いつ？

事件のコード `broken_hatch` を、`busy_ranch.py` で見てみよう。

```python
monster = Monster("？", "スライム", (90, 200, 250))   # ← ここで1匹誕生
for egg in eggs:
    monster.name = egg["name"]     # 名前を書きかえる
    ranch.append(monster)          # 名簿に入れる
```

`Monster(...)` は、`for` の **外** に1回しか書いていない。
だから、誕生したのは **1匹だけ**。

`for` の中でしていたのは、

1. 同じ1匹の名前を、ポコ → ミミ → ルル と書きかえる
2. 同じ1匹を、名簿に3回入れる

ということだったんだ。最後の名前がルルだから、名簿は全員ルルに見えたわけ。

> 💡 **新しい子が誕生するのは、`Monster(...)` を実行した時だけ。**
> 名前を書きかえても、名簿に入れても、子は増えない。

## 🧩 書く前に② 変数は「名札」

第04章で、`piko` は誕生した子につけた **名札** だと話したね。
この章では、名札の話をもう一歩すすめるよ。

```python
piko = Monster("ピコ", "スライム", (90, 200, 250))
guest = piko
```

`guest = piko` は、新しい子を誕生させていない。
**ピコに、もう1枚 `guest` という名札をつけた** だけなんだ。

```text
  piko  ──┐
          ├──→ 🟦 ピコ（HP 4）
  guest ──┘
```

だから `guest.eat(3)` をすると、ピコの HP も増える。名札はちがっても、本人は1匹だからね。

リストも同じ。`ranch = [piko, momo]` は、ピコとモモを **コピーして** 箱に入れたのではなく、
**名札を並べた名簿** なんだ。`ranch[0]` も、ピコを指すもう1枚の名札だよ。

`for member in ranch:` の `member` も、名簿を上から順番に指していく **名札** だよ。
`member.eat(2)` と書くと、そのとき `member` が指している子が `self` になって食べるんだ。

## 🔍 書く前に③ 「同じ本人？」は `is` で聞く

名札がたくさんあると、「この2枚の名札、同じ子についてる？」と知りたくなるね。
それを聞くのが **`is`**（イズ）だよ。

```python
piko  = Monster("ピコ", "スライム", (90, 200, 250))
guest = piko
twin  = Monster("ピコ", "スライム", (90, 200, 250))

print(piko is guest)   # True  ← 同じ本人に、名札が2枚
print(piko is twin)    # False ← 名前も色も同じだけど、別々に誕生した子
```

`twin` は、名前・種族・色がピコとまったく同じ。
でも `Monster(...)` を **別に1回実行した** から、別の子なんだ。
たとえば双子は、顔がそっくりでも別の人だよね。

| 聞きたいこと | 使うもの | 例 |
|---|---|---|
| 名前（文字）や数が同じ？ | `==` | `piko.name == twin.name` → `True` |
| **同じ本人？** | **`is`** | `piko is twin` → `False` |

数や文字を比べる時は、これまで通り `==` を使おう。
**モンスターが同じ本人かどうか** を聞きたい時だけ、`is` を使うよ。

## 🔍 書く前に④ 数字ではなく「その子」を返す

これまでの関数は、数字や `True` / `False` を `return` してきたね。
でも、関数は **モンスターそのもの** を返すこともできる。

```python
patient = weakest(ranch)   # いちばん弱っている「その子」が返ってくる
patient.sleep()            # その子に、そのまま眠ってもらえる！
```

もし `weakest` が HP の数字（`1`）を返したら、「1って……だれの HP？」となって、
その子に `sleep()` を頼めない。
**「その子」を返せば、受け取った名札で、すぐ仕事を頼める** んだ。

---

## 📇 ことばカード

| ことば | 意味 | この章では |
|---|---|---|
| 名札 | 子を指す変数。何枚でもつけられる | `piko`、`guest`、`ranch[0]` |
| 本人 | `Monster(...)` で誕生した、その1匹 | 名札が何枚でも、本人は1匹 |
| `is` | 2つの名札が **同じ本人** を指しているか | `piko is guest` → `True` |
| `==` | 数や文字が **同じ値** か | `piko.name == twin.name` → `True` |

## 💡 書いた後に: 何が起きたの？

### 事件1の解決: `Monster(...)` を、毎回実行した

`hatch_one` は、タマゴ1個ごとに呼ばれて、そのたびに `Monster(...)` を実行する。
だから、ポポ・ピコ・ナナ・ララが **4匹の別々の子** として誕生した。
事件のコードとのちがいは、`Monster(...)` が **何回実行されたか** だけなんだ。

### 事件2の解決: 名札が2枚でも、本人は1匹

`guest = piko` で作った `guest` は、ピコについたもう1枚の名札。
`already_here` が `is` で調べたから、「もう名簿にいる本人だ」と気づけたね。

一方、タマゴから生まれたドラゴンの「ピコ」は、名前が同じでも **別の本人**。
だから名簿に入れたし、名簿にも「← 先輩と同じ名前の、別の子！」と出た。
もし名前（`==`）で調べていたら、この子は追い返されていたよ。

### 「その子」を返したから、すぐお世話できた

`weakest` は、HP の数字ではなく **スライムのピコ本人** を返した。
だから `patient.sleep()` と、そのまま眠ってもらえたんだ。
同じ名前のドラゴンのピコは眠らなかったよね。**本人を選んだ** からだよ。

### クラスは1行も変えていない！

この章では、`Monster` の設計図を **1行も** 書きかえていない。
それでも、2匹だった牧場が6匹になって、全員がちゃんと別々に遊んだり食べたりした。
1つの設計図から、何匹でも誕生させられる。これがクラスの力だよ。

## ⚠️ ありがちなまちがい

<details>
<summary>⚠️ クリックで開く（エラーが出た時や、うまく動かない時に読もう）</summary>

### ① 名簿そのものに `eat` を頼んだ

```python
ranch.eat(2)
```

```text
AttributeError: 'list' object has no attribute 'eat'
```

「リスト（list）は eat を持っていない」という意味。
ごはんを食べられるのはモンスターで、名簿（リスト）は食べられない。`for` で1匹ずつ頼もう。

### ② `return` を忘れた

```python
def hatch_one(egg):
    Monster(egg["name"], egg["kind"], egg["color"])
```

1匹誕生するけど、だれにも名札をつけずに、関数が終わってしまう。
関数は `None`（何もない）を返すので、「🥚 まだ割れない……」のままになるよ。

### ③ `return False` を `for` の中に書いた

```python
for member in ranch:
    if member is monster:
        return True
    return False      # ← 字下げが深すぎる！
```

1匹目が別の子だったら、2匹目以降を見ずに `False` を返してしまう。
`return False` は、**全員を見終わった後**（`for` と同じ字下げ）に書こう。

### ④ 空の名簿の1番目を見た

```python
result = ranch[0]     # ranch が空っぽだと……
```

```text
IndexError: list index out of range
```

「リストの番号が、範囲の外だよ」という意味。だれもいない名簿に1番目はいないよね。
先に `if len(ranch) == 0: return None` で確かめよう。

### ⑤ `append` の結果を名簿に入れた

```python
ranch = ranch.append(baby)
```

エラーにならないけど、`ranch` が `None` になってしまう。
`append` は「追加する」仕事をするだけで、新しいリストは返さないんだ。`ranch.append(baby)` だけでOK。

</details>
