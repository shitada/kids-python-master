## 🤔 書く前に① 変数だけで、3匹育ててみると……

いままでの知識で、3匹のモンスターを育ててみよう。
1匹につき「名前・HP・レベル」の3つを覚えたいとすると、こうなるね。

```python
m1_name = "ピコ"
m1_hp = 10
m1_level = 1

m2_name = "モモ"
m2_hp = 10
m2_level = 1

m3_name = "ガブ"
m3_hp = 10
m3_level = 1
```

3匹で、もう **9個** の変数。
ここで、ピコにごはんをあげるコードを書いたとしよう。

```python
# ピコにごはんをあげる
m1_hp = m2_hp + 3   # ← あれ？
```

よーく見ると、**ピコ（m1）のHPを、モモ（m2）のHPから計算している**！
でもPythonは、何も教えてくれない。エラーにならずに動いてしまうんだ。😱

困っているのは、こういうこと。

- `m1_hp` と `m1_name` が「同じ1匹の情報」だと、Pythonは知らない
- 名前が少しちがうだけの変数が、モンスターが増えるたびにどんどん増える

ここで、こう思えたら最高だよ。

> 💭 **「1匹分の情報を、1つにまとめて持っておけたらいいのに……」**

それをかなえるのが、**クラス** だよ。

## 🧩 書く前に② クラス＝設計図、インスタンス＝誕生した1匹

たい焼き屋さんを思い浮かべてみよう。🐟

- **たい焼きの型** は1つ。でも、そこから何個でもたい焼きが焼ける
- 焼けたたい焼きは、1個1個が別のもの。あんこの子も、クリームの子もいる
- **型そのものは食べられない**

プログラムでも同じだよ。

| たい焼き屋さん | モンスター牧場 | Pythonでは |
|---|---|---|
| たい焼きの型 | モンスターの設計図 | **クラス** `Monster` |
| 焼けた1個 | 誕生した1匹 | **インスタンス** `Monster("ピコ", ...)` |
| あんこ・クリーム | 名前・種族・色・HP | **属性** `piko.name` など |

たとえ話はここまで。すぐにコードで確かめよう。
今回のファイルには、こんな設計図が書いてあるよ。

```python
class Monster:
    def __init__(self, name, kind, color):
        self.name = name
```

そして、この設計図から1匹を誕生させているのが、この行。

```python
piko = Monster("ピコ", "スライム", (90, 200, 250))
```

この行には、**3つの別のもの** が登場しているよ。ここが一番大事！

| 書き方 | 何のこと？ | たい焼きで言うと |
|---|---|---|
| `Monster` | 設計図（クラス） | 型 |
| `Monster("ピコ", ...)` | 設計図を使って、**いま1匹を誕生させる** | 型で1個焼く |
| `piko` | 誕生した1匹につけた **名札**（変数） | 焼けた1個に「ピコ」と書いた札 |

> 💡 **クラスの名前は大文字で始める** のがPythonのお約束。
> `Monster` が大文字なのは「これは設計図だよ」という目印なんだ。

## 🔍 書く前に③ 誕生の瞬間に、何が起きている？

`Monster("ピコ", "スライム", (90, 200, 250))` と書くと、
Pythonはこっそり、次の4つを順番にやっているよ。

```text
① まだ何も持っていない、空っぽの1匹を作る
        ↓
② その1匹を self という名前にして、__init__ を呼ぶ
   （name="ピコ", kind="スライム", color=(90, 200, 250) もいっしょに渡す）
        ↓
③ __init__ の中で、self.name = name などが実行される
   → その1匹が、名前や種族を「覚える」
        ↓
④ 準備ができた1匹ができあがり、piko という名札がつく
```

### `__init__`（イニット）は「誕生セット係」

`__init__` は、**1匹が誕生するたびに自動で1回だけ動く** 特別な関数だよ。
自分で `__init__(...)` と呼ばなくても、`Monster(...)` と書けば勝手に動く。
「生まれたらすぐ、この子に名前と種族を覚えさせてね」という仕事を任される係なんだ。

`init` は「initialize（イニシャライズ）＝はじめの準備をする」の略。
前後の `__`（アンダーバー2つ）は、「Pythonが特別に使う名前だよ」という印だよ。

### `self`（セルフ）は「いま生まれている、その1匹」

`__init__` の中に出てくる `self` が、いちばん不思議に見えるところ。
`self` には、**②で作られた「いま誕生しているその1匹」** が入っているよ。

ピコを誕生させている時は、`self` ＝ ピコ。
モモを誕生させている時は、`self` ＝ モモ。
設計図は1つなのに、誕生させる子によって `self` の中身が入れかわるんだ。

### `self.name = name` の、左と右

この1行は、左と右で意味がちがうよ。

```python
self.name = name
```

| 場所 | 意味 |
|---|---|
| 右の `name` | `Monster("ピコ", ...)` で **受け取った値**（"ピコ"） |
| 左の `self.name` | **この1匹の持ち物** として用意した「名前の箱」 |

つまり、「受け取った "ピコ" を、**この子の名前の箱** にしまってね」という意味。
右の `name` は、`__init__` が終わると消えてしまう。
でも `self.name` にしまったものは、**その子がずっと覚えている** よ。

こうして、その子がずっと覚えている情報のことを **属性（ぞくせい）** と呼ぶよ。

### `.`（ドット）は「〜の」と読もう

属性を使う時は、`piko.name` のように **ドット** でつなぐ。

- `piko.name` → **ピコの** 名前
- `piko.hp` → **ピコの** HP
- `buddy.level` → **2匹目の** レベル

変数の時は `m1_hp` という名前の工夫で「誰の」を表していたね。
クラスなら、**ドットの左に誰の情報かがはっきり書いてある**。
これで、さっきの「ピコとモモを取りちがえる事件」が起きにくくなるんだ。

## 💡 書いた後に: 何が起きたの？

全部 ✅ になったら、画面とコードを見比べてみよう。

### 1つの設計図から、ちがう子が生まれた

ピコと2匹目は、**同じ `Monster` という設計図** から生まれたのに、
名前も、顔も、色もちがったね。

```python
piko  = Monster("ピコ", "スライム", (90, 200, 250))
buddy = Monster("モモ", "おばけ",   (255, 160, 200))
```

設計図が決めているのは **「どんな属性を持つか」** だけ。
**属性の中身（値）** は、1匹ずつちがっていい。
これが「クラス」と「インスタンス」の関係だよ。

### 2匹は、別々の持ち物を持っている

TODO 4 で、ピコだけがレベル2になったね。
`piko.level` と `buddy.level` は、名前は同じ `level` でも、**別々の箱** なんだ。

```text
  ピコ（piko）             モモ（buddy）
 ┌─────────────────┐    ┌─────────────────┐
 │ name  : "ピコ"   │    │ name  : "モモ"   │
 │ kind  : "スライム"│    │ kind  : "おばけ" │
 │ hp    : 10      │    │ hp    : 10      │
 │ level : 2  ← ✨ │    │ level : 1       │
 └─────────────────┘    └─────────────────┘
```

もし3匹目、4匹目を誕生させても、変数は `Monster(...)` 1行ずつ増えるだけ。
最初の「9個の変数」と比べてみよう。ずいぶんスッキリしたよね。

### 設計図に書いたから「忘れない」

`__init__` に `self.hp = 10` と書いたことで、
**どの子も、生まれた瞬間に必ず HP を持つ** ようになった。
変数で育てていた時は、新しい子の `m4_hp` を作り忘れても気づけなかった。
設計図に書いておけば、作り忘れがなくなるんだ。

## 🔬 観察コーナー: 設計図に書かないと、どうなる？

ここは読むだけでOK。興味がある人は、ターミナルで `python` と入力して試してみてね。
（おわる時は `exit()` と入力する）

実はPythonでは、**何も書いていない空っぽの設計図** も作れるよ。
`pass` は「ここには何も書かない」という意味。

```python
>>> class Box:
...     pass
...
>>> b = Box()
>>> b.name = "なぞの箱"
>>> b.name
'なぞの箱'
```

誕生した後から、外で属性をくっつけることもできてしまう。
でも、これだと「Boxは何を覚えているか」が、**設計図を見ても分からない**。
もう1個 Box を作った時、`name` をつけ忘れてもPythonは教えてくれない。

だからこの教材では、**属性は `__init__` の中で用意する** ことにしているよ。
「設計図を見れば、その子が何を覚えているか全部分かる」状態が、いちばん安心なんだ。

> 🔎 おまけ: `vars(b)` と入力すると、`{'name': 'なぞの箱'}` のように、
> その子が持っている属性を全部見せてくれる。第06章でくわしく使うよ。

## ⚠️ ありがちなまちがい

エラーが出たら、**赤い文字の一番最後の行** を読もう。何が起きたかが書いてあるよ。

### ① 引数が足りない

```python
piko = Monster("ピコ", "スライム")
```

```text
TypeError: Monster.__init__() missing 1 required positional argument: 'color'
```

「`__init__` に渡す `color` が **1個足りない**（missing）」という意味。
`__init__(self, name, kind, color)` だから、**自分で渡すのは3つ**。
`self` はPythonが自動で渡すから、数えなくていいよ。

### ② `( )` を忘れた

```python
buddy = Monster
```

これは「設計図そのもの」に名札をつけただけで、**まだ誕生していない**。
`buddy.name` を使おうとすると、こうなるよ。

```text
AttributeError: type object 'Monster' has no attribute 'name'
```

「type object（設計図）は name を持っていない」という意味。
たい焼きの「型」に「あんこは何？」と聞いているようなものだね。

### ③ `self.` を忘れた

```python
def __init__(self, name, kind, color):
    name = name      # ← self. がない！
```

これだと、受け取った値をしまう場所が「この子の箱」ではなく、
`__init__` が終わると消えてしまう、ただの変数になってしまう。
後で `piko.name` を使うと、こう言われるよ。

```text
AttributeError: 'Monster' object has no attribute 'name'
```

「Monsterのインスタンスは name を持っていない」＝ **この子は覚えていない** という意味。

### ④ 属性の名前を書きまちがえた

```python
print(piko.kindd)
```

```text
AttributeError: 'Monster' object has no attribute 'kindd'. Did you mean: 'kind'?
```

「`kindd` という属性はないよ。**もしかして `kind` のこと？**」という意味。
Pythonが、近い名前を見つけてヒントをくれているんだ。
エラーに出ている名前（`kindd`）と、`__init__` で書いた名前（`kind`）を比べてみよう。

### ⑤ `=` と `==` をまちがえた

```python
self.hp == 10     # ← = が2つ！
```

```text
AttributeError: 'Monster' object has no attribute 'hp'
```

`==` は「同じ？」と **たずねる** 記号で、何も入れてくれない。
だから、この子は HP を持たないまま。**箱に入れる時は `=` を1つ** だよ。

## 🕵️ バグ探しクイズ

次のコードを実行すると、ピコの色がおかしくなる。どこが悪い？

```python
class Monster:
    def __init__(self, name, kind, color):
        self.name = name
        self.kind = color
        self.color = kind
```

<details>
<summary>こたえを見る</summary>

`self.kind = color` と `self.color = kind` が **入れかわっている**。
Pythonは「種族の箱に色が入っている」ことには気づけないから、エラーにならない。
`self.○○ = ○○` は、左右で **同じ名前** になっているか確かめよう。

</details>
