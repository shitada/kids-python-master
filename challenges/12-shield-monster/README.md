## 📖 今回の事件

バリアでダメージを少しへらせるモンスター **ガード** を作ろう！ 🛡️
ガードには、ほかの子にはない「バリアの残り回数」が必要。
スタッフが、子クラスに `__init__` を書いて、バリアを持たせた。実行してみよう。

```text
🔎 vars でのぞくと: {'shield': 2}
🍎 ガード「おなかすいた！ ごはんを食べよう」
   💥 AttributeError: 'BrokenShield' object has no attribute 'hp'
😱 バリアは持っているのに、HP がない！？
```

事件のコードを見てみよう。

```python
class BrokenShield(Monster):
    def __init__(self, name, kind, color):
        self.shield = 2
```

`vars` でのぞくと、ガードが持っているのは `shield` だけ。
`name` も `hp` も、どこにもない！ ごはんを食べようとして、`self.hp` が見つからずに止まってしまった。

Monster を受けついだのに、なぜ HP がないんだろう？ 🕵️

## 🤔 書く前に① 子が `__init__` を書くと、親の `__init__` は動かない

第11章のフワは、`__init__` を書かなかった。
だから `FloatingMonster(...)` で誕生した時、Pythonは親の `__init__` を探して使ってくれた。

でも、事件のガードは、子クラスに `__init__` を **書いた**。
第11章で学んだ「オーバーライド」が、`__init__` にも起きたんだ。

```text
BrokenShield("ガード", ...)
  ① BrokenShield に __init__ はある？ → ある！ これを使う
     → self.shield = 2 だけ実行
  ② 親の Monster の __init__ は……   → 探しに行かない！（name や hp は作られない）
```

> ⚠️ 子クラスに `__init__` を書いても、**親の `__init__` は自動では動かない**。
> ここが、いちばんのつまずきポイントだよ。

---

## 🧩 書く前に② `super()` で、親に頼む

子の `__init__` の中から、親の `__init__` に「準備をお願い！」と頼む方法が **`super()`**（スーパー）だよ。

```python
class ShieldMonster(Monster):
    def __init__(self, name, kind, color):
        super().__init__(name, kind, color)    # 親（Monster）の誕生準備をお願い！
        self.shield = 2                        # そのあと、自分だけの準備
```

`super()` は「**自分の親クラス**」を指す呼び方。
`super().__init__(name, kind, color)` で、Monster の `__init__` が動いて、
`name`・`kind`・`color`・`level`・`max_hp`・`hp`・`happy` が用意されるよ。

```text
ShieldMonster("ガード", "スライム", 色)
  ① ShieldMonster の __init__ が動く
       super().__init__(...)  → 親の __init__ で name・hp などを用意
       self.shield = 2        → 自分だけのバリアを用意
  ② 誕生完了！ 親の属性 ＋ 自分の属性 を、ぜんぶ持っている
```

### `super()` は、別の子を作らない

`super().__init__(...)` は、**新しいモンスターを誕生させるわけではない**。
いま誕生している **同じガード本人** の準備を、親に手伝ってもらうだけなんだ。
だから、親が用意した `self.hp` も、子が用意した `self.shield` も、同じガードが持っているよ。

## 🔍 書く前に③ 親の仕事の前に、ひと工夫

次は、ダメージの受け方。バリアのルールはこうだよ。

| ルール | 内容 |
|---|---|
| バリアが残っていて、ダメージが 0 より大きい | ダメージを **1 へらして**、バリアを1回使う |
| それ以外 | ダメージはそのまま |
| HP の減らし方 | **親と同じ**（0 より小さくしない、本当に減った量を返す） |

HP の減らし方は、親の `take_damage` がもう知っている。
だから、ガードの `take_damage` では、**バリアの計算だけ** を書いて、残りは親に頼めばいい。

```python
def take_damage(self, amount):
    if amount > 0 and self.shield > 0:      # 自分だけの仕事（バリア）
        amount = amount - 1
        self.shield = self.shield - 1
    return super().take_damage(amount)      # 親の仕事（HP を減らす）に頼む
```

> 🍛 カレー屋さんで考えよう。ふつうのカレーの作り方は、お店の決まり（親）。
> 「辛口」は、最後にスパイスを足すだけ（子）。カレーの作り方を、一から書き直したりしないよね。

---

## 🔍 書く前に④ 親の答えを、そのまま返す

親の `take_damage` は、**本当に減った量** を `return` してくれる（第08章）。
ガードの `take_damage` も、同じ約束を守りたい。だから、親の答えを **そのまま `return`** するんだ。

```python
return super().take_damage(amount)
```

もし `return` を忘れると、`take_damage` の答えが `None` になってしまう。
たいあたりのログに「本当に減ったのは None」と出てしまうよ。

親の答えを返すことで、ガードも **ほかのモンスターと同じ約束（合図）** で使える。
`tackle` は、相手がガードかどうかを調べずに `other.take_damage(power)` と頼むだけで済むんだ。

## 📇 ことばカード

| ことば | 意味 | この章では |
|---|---|---|
| `super()` | 自分の親クラスを指す呼び方 | `super().__init__(...)` |
| 親に頼む | 親クラスのメソッドに、仕事の一部をお願いすること | `super().take_damage(amount)` |
| 子だけの属性 | 子クラスの `__init__` で足す、新しい属性 | `self.shield` |

## 💡 書いた後に: 何が起きたの？

### 事件の解決: 親の準備 ＋ 自分の準備

```python
super().__init__(name, kind, color)    # 親の準備: name・hp など
self.shield = 2                        # 自分の準備: バリア
```

親の準備を `super()` で頼んだから、ガードは HP も名前も持てた。
そのあとに、自分だけのバリアを足した。**親の仕事を使って、足す** の形だね。

もし `super()` を使わずに、Monster の `__init__` の中身を全部コピーしたら？
第11章の事件と同じで、親を直した時にコピーが古いまま残ってしまう。

### ガードの `take_damage` は、たったの4行

ガードの `take_damage` に書いたのは、**バリアの計算だけ**。
「0 より小さくしない」「本当に減った量を返す」というルールは、親の `take_damage` に任せた。

```text
モモの tackle(ガード)
 └ ガード.take_damage(5)          ← ShieldMonster の take_damage（オーバーライド）
     ├ バリアで 5 → 4             ← 自分の仕事
     └ super().take_damage(4)     ← 親の仕事（HP 10 → 6、答えは 4）
```

### 子クラスの書き方、3つの形

これで、子クラスのメソッドの書き方が3つそろったよ。

| 形 | 書き方 | 例 |
|---|---|---|
| ① 書かずに受けつぐ | 子に何も書かない | フワの `eat`・ガードの `sleep` |
| ② 全部書きかえる | 親と同じ名前で、中身を全部書く | フワの `play`（第11章） |
| ③ 親を使って、足す | 同じ名前で書いて、中で `super()` を呼ぶ | ガードの `__init__`・`take_damage` |

どれを選ぶかは、「親の仕事を **そのまま** 使うか、**全部** 変えるか、**少し足す** か」で決めよう。
③の形を使うと、親のルールを守ったまま、自分らしさを足せるよ。

### フワとガード、親は同じ

最後に、フワもたいあたりを受けたね。フワは `take_damage` を書きかえていないので、親のルールのまま 5 減った。
同じ Monster を親に持っていても、**書きかえたところだけ** がちがう。これが継承の便利なところだよ。

<details>
<summary>🎁 おまけ: super() を、ほかのメソッドでも使ってみよう（クリックで開く）</summary>

ガードが眠ったら、HP だけでなく、バリアも回復するようにしてみよう。

```python
class ShieldMonster(Monster):
    ...
    def sleep(self):
        super().sleep()                 # 親の仕事: HP を満タンにして「すやすや」と表示
        self.shield = 2                 # 自分の仕事: バリアも回復
        print(f"🛡️ {self.name} の バリアも回復した！")
```

`super()` は、`__init__` 専用ではないよ。**どのメソッドでも**、親の同じ名前のメソッドを呼べる。
親の仕事の **後に** 足すことも、**前に** 足すこともできる（`take_damage` は前に足したね）。

</details>

## ⚠️ ありがちなまちがい

<details>
<summary>⚠️ クリックで開く（エラーが出た時や、うまく動かない時に読もう）</summary>

### ① `super().__init__` に、引数を渡し忘れた

```python
super().__init__(name)
```

```text
TypeError: Monster.__init__() missing 2 required positional arguments: 'kind' and 'color'
```

「親の `__init__` に、`kind` と `color` が足りない」という意味。親が受け取るものは、全部渡そう。

### ② `super` のうしろの `()` を忘れた

```python
super.__init__(name, kind, color)
```

```text
TypeError: descriptor '__init__' requires a 'super' object but received a 'str'
```

むずかしいエラー文だけど、原因はかんたん。`super()` のように **カッコをつけよう**。

### ③ `self.shield = 2` を、`super().__init__` より前に書いた

これは動くけど、親の `__init__` がもし `shield` という属性を作っていたら、上書きされてしまう。
**親の準備 → 自分の準備** の順番がおすすめだよ。

### ④ `return` を忘れた

```python
super().take_damage(amount)       # ← return がない！
```

HP は減るけど、答えが `None` になる。ログに「本当に減ったのは None」と出たら、`return` を確かめよう。

</details>
