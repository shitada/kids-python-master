## 🎯 この章でできるようになること

- モンスター以外の物（道具）にも、**メソッドで仕事を頼める**
- 種類がちがうクラスでも、**メソッドの名前と使い方（約束）をそろえれば**、同じように使える
- 使う側は「それが何の道具か」を調べずに、**同じ合図で頼むだけ** でよくなる
- 新しい道具が増えても、使う側のコードを **1行も直さずに** 動かせる

## 📖 今回の事件

ミナのトレーナー部屋に、ボール・おやつに加えて、新しい道具 **パズル** が届いた！ 🧩
さっそく、受付係と配る係が、パズルを使ってみる。実行してみよう。

```text
🧩 受付係「ピコ、パズルをどうぞ！」
⚽ ピコ は 元気に遊んだ！ ごきげん 60  HP 10 → 7
🍎 ピコ は もぐもぐ…… HP 7 → 8

🎒 配る係「ミナのチームのみんな、パズルをどうぞ！」
   ……（シーン）
😱 受付係は直したのに、配る係はパズルを知らない！
```

受付係ではパズルが使えたのに、配る係では何も起きない。
事件のコードを見てみよう。

```python
def broken_use(tool_name, monster):        # 受付係
    if tool_name == "ボール":
        monster.play()
    elif tool_name == "おやつ":
        monster.eat(3)
    elif tool_name == "パズル":            # ← パズルを足した！
        ...

def broken_hand_out(trainer, tool_name):   # 配る係
    for member in trainer.team:
        if tool_name == "ボール":
            ...
        elif tool_name == "おやつ":
            ...
        # ← パズルを足すのを、忘れている！
```

道具の **使い方を知っているのが、係の人たち** なんだ。
だから、道具が1つ増えるたびに、係の人の `if` を **全部** 直さないといけない。
1か所でも忘れると、こうなってしまう。😱

## 🤔 書く前に① 道具にも、仕事を頼める

これまでメソッドを持っていたのは、モンスターとトレーナーだったね。
でも、**道具もクラスにして、メソッドを持たせられる** よ。

お手本の `Ball`（ボール）を見てみよう。

```python
class Ball:
    def __init__(self):
        self.name = "ボール"
        self.icon = "🎾"

    def use(self, monster):
        if monster.is_tired():
            return False
        monster.play()
        return True
```

使う時は、こう書く。

```python
ball = Ball()
ball.use(piko)        # ボール、ピコに使って！
```

第08章と同じ読みかえで考えよう。

```text
ball.use(piko)   →   Ball.use(ball, piko)
                              │      │
                            self   monster
```

`use` の中の `self` は **ボール**、`monster` は **ピコ** だよ。
道具のメソッドだから、`self` はモンスターではなく、道具自身なんだ。

---

## 🧩 書く前に② 合図（約束）をそろえる

`Ball` のほかに、`Snack`（おやつ）と `Puzzle`（パズル）も、同じ形で作るよ。
3つの道具は、使い方の中身はバラバラ。でも、**約束** だけはそろえるんだ。

| 約束 | 内容 |
|---|---|
| メソッドの名前 | どれも `use` |
| 受け取るもの | 使う相手のモンスター（`monster`）1匹 |
| 返す答え | 使えたら `True`、使えなかったら `False` |

| 道具 | `use(monster)` の中身 |
|---|---|
| 🎾 ボール | つかれていたら `False`。元気なら遊んで `True` |
| 🍪 おやつ | `self.amount` ぶん食べて `True` |
| 🧩 パズル | つかれていたら `False`。元気なら遊んで、一口食べて `True` |

約束がそろっていれば、使う側は **どの道具でも `tool.use(monster)` と書くだけ** でいい。

> 📺 テレビのリモコンを思い出そう。テレビの会社がちがっても、「電源ボタン」を押せばつく。
> 中のしくみはバラバラでも、**押すボタン（合図）がそろっている** から、だれでも使えるんだ。

---

## 🔍 書く前に③ 使う側は、種類を調べない

約束がそろうと、使う側のコードは、こんなにスッキリする。

```python
for tool in tools:
    tool.use(monster)     # ボールか、おやつか、パズルか……調べない！
```

事件のコードでは、係の人が `if tool_name == "ボール":` と **種類を調べて** いた。
でも、ここでは `tool` が何の道具なのか、まったく調べていない。

それでも、ボールならボールの `use`、パズルならパズルの `use` が、ちゃんと動く。
**`tool.use(...)` と頼むと、ドットの左の道具自身が、自分の `use` を使う** からだよ（第05章の `self` のしくみ）。

このように、**同じ合図で頼んでも、相手によってちがう動きをすること** を、
むずかしい言葉で **ポリモーフィズム**（いろいろな形になる、という意味）と呼ぶよ。

---

## 🔍 書く前に④ 道具も、モンスターに頼む

おやつの `use` で、モンスターの HP を増やしたい時、どう書く？

```python
monster.hp = monster.hp + self.amount      # ❌ 外から直接さわる
monster.eat(self.amount)                   # ⭕ モンスターに頼む
```

第08章で学んだね。**相手の値は、相手のメソッドに頼む**。
`eat` に頼めば、「HP は `max_hp` より多くならない」ルールが必ず守られる。

道具は「だれに、何をしてもらうか」を知っている。
モンスターは「どうやって食べるか、遊ぶか」を知っている。
ここでも、**仕事は知っている人に任せる** がキーワードだよ。

## 📇 ことばカード

| ことば | 意味 | この章では |
|---|---|---|
| 合図（メソッド名） | 使う側が頼む時の決まった呼び方 | `use(monster)` |
| 約束 | 名前・受け取るもの・返す答えをそろえること | 名前は `use`、答えは `True` / `False` |
| ポリモーフィズム | 同じ合図で、相手によってちがう動きをすること | `tool.use(piko)` |

## 💡 書いた後に: 何が起きたの？

### 事件の解決: 使い方を知っているのは、道具自身

事件のコードでは、**係の人** が道具の使い方を知っていた。
今は、**道具自身** が自分の使い方（`use`）を知っている。
だから `use_all` も `use_on_team` も、「使って！」と頼むだけで済んだ。

| | 事件のコード | 君のコード |
|---|---|---|
| 使い方を知っているのは | 係の人（`if` の中） | 道具自身（`use` メソッド） |
| 道具が増えたら | 係の人の `if` を全部直す | 新しい道具のクラスを1つ作るだけ |

### 最後のおどろき: 知らない道具が、動いた！

最後に届いた **ふうせん** 🎈 は、`ranch_tools.py` の中で作られた道具。
`same_signal.py` のどこにも、ふうせんのことは書いていない。

それなのに、`use_all` でも `mina.use_on_team` でも、ふうせんがちゃんと使えたね。
ふうせんも **`use(monster)` という同じ合図を持っていた** から、それだけで仲間に入れたんだ。

```text
✨ use_all も Trainer も、1行も直していないのに、新しい道具が動いた！
```

これが、合図をそろえることの、いちばんのよさだよ。🎉

### 実は、もう使っていた！

第06章で、`print(piko)` も `print("こんにちは")` も `print(10)` も、同じ `print` で表示できたね。
`print` は、相手がモンスターでも文字でも数でも、「自己紹介して（`__str__`）」と同じ合図を送るだけ。
**Pythonそのものが、ポリモーフィズムで作られている** んだ。

プログラマーの世界には、こんなことわざがあるよ。

> 🦆 **アヒルのように歩き、アヒルのように鳴くなら、それはアヒルだ。**

`use_all` は、相手が `Ball` か `Snack` か、まったく気にしていない。

このことわざから、この考え方を **ダックタイピング**（アヒルの型）と呼ぶよ。

## ⚠️ ありがちなまちがい

<details>
<summary>⚠️ クリックで開く（エラーが出た時や、うまく動かない時に読もう）</summary>

### ① メソッドの名前が、約束とちがう

```python
class Puzzle:
    def use_puzzle(self, monster):     # ← use ではない！
        ...
```

```text
AttributeError: 'Puzzle' object has no attribute 'use'
```

「Puzzle は use を持っていない」という意味。
約束の名前（`use`）とちがうと、同じ合図で呼べなくなる。名前は **ぴったり同じ** にしよう。

### ② 受け取るものの数が、約束とちがう

```python
def use(self):          # ← monster を受け取っていない！
```

```text
TypeError: Puzzle.use() takes 1 positional argument but 2 were given
```

使う側は `tool.use(monster)` と、**モンスターを1匹渡して** くる。受け取る準備をしておこう。

### ③ `return` を忘れた

```python
def use(self, monster):
    monster.eat(self.amount)        # ← return がない！
```

エラーにならないけど、答えが `None` になって「❓ None（True か False を返そう）」と表示される。
約束どおり、使えたら `return True` しよう。

### ④ `use_all` の中で、種類を調べた

```python
for tool in tools:
    if tool.name == "ボール":
        ...
```

動くかもしれないけど、事件のコードに逆もどり！ 新しい道具（ふうせん）が来ると動かなくなる。
**種類は調べず、`tool.use(monster)` と頼むだけ** にしよう。

</details>
